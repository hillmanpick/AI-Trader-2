# 全市场研究、动态杠杆与独立模拟

实盘继续只读。采集器、训练器和模拟进程的 Docker 环境明确清空币安密钥；`PaperMarket` 仅允许公开 GET 接口。这里不提供真实订单或实盘启用功能。

## 数据链路

1. `exchangeInfo` 获取全部状态为 TRADING、USDT 保证金与报价的永续合约，保留精度、步长与最小订单规则。
2. 全市场 `!ticker@arr` 提供成交额动态扫描；每 5 分钟刷新候选池，默认成交额至少 2,000 万 USDT、最多 12 个币。BTC 用于市场状态参照。轮换时保留已有持仓的行情订阅。
3. 候选订阅 `market` 通道的 `aggTrade`、`public` 通道的 `bookTicker` 和 `depth@100ms`；REST 深度快照与 diff 序号 U/u/pu 对齐，缺口后立即失效并重建。每分钟重新拉快照，防止初始有限深度长期漂移。盘口数量为价格档位上的聚合数量，不是交易所逐笔挂单数。
4. Redis 保存有 TTL 的最新特征、盘口、候选池和心跳，以有界 Stream 发布跨进程事件。无外部端口；96 MB/noeviction；不可用时禁止模型新仓。历史不会依赖 Redis 恢复。
5. SQLite WAL 保存每 5 秒的候选特征；gzip 保存原始行情与快照。默认历史保留 14 天，原始压缩文件每日约 512 MB 上限，满额后计数并停止当天原始记录；特征继续采集。磁盘不是无限存储，需要在监控中关注 raw_dropped。删除历史按小批次运行。

## 特征与模型

`microstructure-v3` 固定顺序的 14 维数值向量包括 5/30/60 秒收益、EWMA 波动、价差、盘口金额失衡、连续深度更新累积的 5 秒最佳报价 OFI、主动成交失衡、成交量及异常程度、BTC 60 秒收益、双边深度和行情延迟。不是文本 embedding，不需要向量数据库。有限深度可能只覆盖价格带的一部分，此时深度明确标为下界，仓位容量使用该保守下界。v2 的端点 OFI 与 v3 不可混训，升级后旧特征会被 schema 门禁排除。

逻辑回归与向量原型是方向模型：仅用训练段拟合标准化、聚类原型与预测参数。最终训练标签来自全市场单笔 WebSocket 成交路径，而不是 5 秒采样价；上下障碍以首次穿越定方向，达到时限为中性。整个标签窗口必须无 ID 缺口、重连和超时，坏窗口不训练。三个递增研究窗口切分时清除完整标签时域；验证窗和测试窗再单独留给最终逐事件模拟，测试段不调参。可用 `--gradient` 做梯度提升研究比较，但它不绕过事件回放证明。

模型以 JSON 系数保存，不反序列化可执行 pickle。默认至少 10,000 条干净有效标签、7 天历史，每 6 小时训练一次；最终验证窗和测试窗默认各保留 1 小时。三个研究测试折及最终事件验证、独立测试和加倍滑点压力段都必须达到收益门槛。模型绑定杠杆、风险和手续费设置，48 小时过期；特征超过 10 秒、盘口超过 2 秒均禁止新仓。达到数据数量不等于验证通过。

每 30 秒最多保留一条特征向量用于模型拟合，以约束 2 GB 服务器的训练内存；标签本身仍由完整逐笔事件路径计算。早期采样报价回放只是研究筛选，无法重建采样间的排队和部分成交。最终模型只有在历史 Parquet 的独立盘口/逐笔事件回放中，采用真实的接收顺序、盘口深度和后续事件成交，计入数量规则、双边手续费、不利滑点、模拟确认时间、部分成交、共享保证金、相关风险、止损止盈及保守资金费后，才有机会晋级。验证时间窗只选阈值，单独测试窗及压力测试不得调参；不完整行情或残留持仓均判无效。模型权重、执行参数及原始数据段哈希都与证明绑定。模拟确认延迟不是交易所 SLA，也无法看到隐藏流动性；通过历史门槛不保证未来盈利。

## 动态杠杆

每仓保证金仍为 2,000 USDT，总保证金上限 6,000 USDT；山寨币默认杠杆范围 2–20 倍，BTC/ETH 的独立上限为 100 倍。这些是上限，不是目标。策略决定止损距离后，按以下约束取最小值并向下取整：

模拟配置 `QUANT_PAPER_MIN_LEVERAGE=2`、`QUANT_PAPER_MAX_LEVERAGE=20`、`QUANT_PAPER_MAJOR_MAX_LEVERAGE=100` 分别控制下限、普通合约上限和 BTC/ETH 上限。后者默认 100；API 的 `paper_major_max_leverage`、页面、执行引擎和事件回放证明使用同一配置。改变上限会改变执行设置哈希，旧模型证明不能直接复用。更新环境变量后需重建读取该配置的容器。

`名义金额 <= 单仓风险预算 / (止损距离 + 往返费用 + 风险缓冲)`

同时受盘口深度参与率、剩余总名义金额、剩余组合风险和强平缓冲约束。波动越大，允许的杠杆通常越低；无法支持最低杠杆时不开仓。动态 sizing 使用真实 ATR 距离，不能先把 ATR 止损截短来制造高杠杆。模型策略使用与回放相同的短周期波动代理。等待审核后也必须重新计算。最多两个同方向模型仓位，避免所有候选同时同向暴露。

已有仓位保留开仓保证金和杠杆。止损只收紧，不放宽；新仓模型到达标签持有期后退出。模拟没有每日亏损熔断，但单仓止损和组合预算仍然存在。实时模拟账本仍使用既有固定费率和不利滑点，不含真实资金费、完整阶梯维持保证金与实际撮合冲击；回放中的资金费为保守近似，不能与交易所账单等同。

## 运行与检查

服务器路径 `/home/ai-trader-quant`，历史数据在 `deploy/data/lab`。`/api/quant/lab/status` 使用既有操作员认证；页面展示采集、Redis、样本量、缺口、模型与样本外结果。模拟新仓依赖完整 readiness gate，旧仓的退出不依赖模型可用性。

## 为什么不用其他方案

Redis 降低重复读取和进程间传递开销，WebSocket 与事件唤醒减少固定等待；单独增加 Redis 无法消除旧循环的睡眠。当前事件主库使用按小时分区的 Parquet/ZSTD，SQLite 保存特征、标签、目录和幂等检查点，便于单机备份与回放；规模增加后可将已校验 Parquet 导出到 ClickHouse，适合大规模并发分析。数值模型的输入顺序固定且可解释；把每帧行情送给 DeepSeek 会增加延迟、缓存未命中和费用。强化学习暂不使用，因为缺少可信仿真和稳定样本外基准时容易学到模拟器偏差。
