## 当前证据

`X=NA,p=q=0` 是实际观察到的源帧。系统保留原始记录及 ID 连续性，但不将其用于价格收益、成交量和模拟撮合。断线和 ID 缺口按精确范围写入 catalog；最近 1,000 笔可通过公开 REST 补齐，较老区间可以填写独立只读 `BINANCE_MARKET_DATA_KEY` 使用历史成交接口。无法补齐的区间明确为 unresolved，不能声称全历史无缺口。

Parquet/ZSTD 按接收小时分区。`events-v2` 将成交时间保存为 typed `trade_time_ms`，避免每条成交重复保存 `T` 的 JSON；价格数量仍为精确字符串，盘口保留 U/u/pu 和原始附加字段，读取器兼容旧 `events-v1`。`bookTicker` 是深度的最佳价投影，当前不进入长期事件库，避免保存不参与回放或特征的重复帧；depth snapshot/diff 仍完整保存并作为唯一盘口重建证据。写入先落临时文件、fsync、原子改名，再登记 SHA256 与检查点；启动时恢复已落盘而未登记的文件。保留原始接收顺序，补采不会改写当时能看到的信息。队列有界，写盘失败退出并通过持久化成交检查点恢复，不能将内存缓存当成持久化保证。

独立成交路径标签器现用 WebSocket 单笔 `@trade` 价格，而非 5 秒采样价；它从样本起点观察完整三重障碍时域，首次穿越上/下障碍分别标记多/空，否则在到期标记中性。到期以后价格不会回改标签，但必须等到期附近有下一笔成交确认序号连续。跨过成交 ID 缺口、重连、超过 15 秒没有有效价格、零值源帧或回退区间都会使样本无效。REST 补采仅修复档案，不回写当时的特征、实时排序或标签路径。已生成标签与质量原因存到独立 SQLite 表；采集器启动时还会自动从最近约 11 分钟的 Parquet 尾部恢复未落盘标签，较长历史可用 `python -m quant.event_labels --directory /data/lab --start-ms ... --end-ms ...` 重建。标签在线窗口完整后才会出现。

## 技术选择

WebSocket 提供完整逐笔和深度事件；Redis 负责实时共享与唤醒，Parquet 负责长期事件证据，SQLite 负责事务账本与目录。只用 Redis 会缺乏持久回放证据，只用定时快照会丢掉路径与成交顺序。Parquet 比逐行 JSON 减少重复字段和磁盘占用，当前服务器没有额外常驻 ClickHouse 的资源负担，但外部查询和大规模并发分析更适合 ClickHouse。

数值原型与逻辑回归可以固定特征顺序并导出可检查参数；不把每一帧交给大语言模型，以避免网络延迟和 token 成本。协方差模型考虑币间共振，固定同方向仓位数只能作为辅助限制。模拟撮合无法知道隐藏流动性、真实队列或撮合器决策，统计必须标明模拟来源。

配置外部 ClickHouse 后，可重复执行已校验 Parquet 分段导出；导出检查点按服务地址、数据库和表名隔离，命令不会打印连接凭据：

```bash
sudo docker compose -f deploy/compose.yaml exec lab-collector python -m quant.event_export
```

配置 `QUANT_CLICKHOUSE_URL`、数据库/表和凭据后，可用 `--profile clickhouse up -d clickhouse-exporter` 启动持续导出 worker；它每 60 秒（可由 `QUANT_CLICKHOUSE_EXPORT_INTERVAL_SECONDS` 调整，范围 10–3600 秒）扫描校验过的分片，成功后登记本地检查点，远端失败时保留待导出状态并重试。默认 Compose 不启用该 profile，所以未配置外部服务时不会新增常驻进程。

导出器只注入事件库及 ClickHouse 配置，不继承整份 `.env` 中的交易、AI 或邮箱密钥。持续模式会在网络、文件或校验异常后等待重试，日志仅包含固定说明和异常类别，不打印异常原文。已有成功分片的检查点保留；重试不承诺本轮失败前没有任何分片成功。间隔 0 也被拒绝，避免错误地回退为默认值。

本次导出器修订后的完整后端回归为 362 passed、2 skipped。插入失败测试按 SQL 类型精确注入失败，避免新增补列步骤后测试实际只验证了建表/补列失败；三类异常重试及零/越界间隔均覆盖。

研究页现在展示 ClickHouse 本地检查点：仅统计当前仍保留的 Parquet 分片、当前目标已导出数和待导出数。统计在一条 SQLite 聚合查询的同一快照中完成，不逐个加载目录，也不在刷新页面时连接外部服务。`configured=true` 仅表示设置了地址，不是连通性或远端数据完整性的证明。URL、用户名和密码不会出现在返回的进度中，目标只用 SHA256 标识。

导出目录的旧版 `path` 主键会事务迁移为 `(target,path)`，保留已有检查点，切换数据库或表后不会覆盖原目标进度。只有成功的 HTTP 导入才登记本地完成状态；失败仍待重试。服务端已经接受但客户端未登记的重试可能重复插入；`ReplacingMergeTree` 的逻辑去重查询需要使用 `FINAL`（或等待合并），不能把未启用服务端去重时的 insert token 当作立即消除物理重复的保证。

本轮本地回归 355 passed、2 skipped，前端生产构建通过。用服务器拉取的 `clickhouse/clickhouse-server:25.8-alpine` 镜像在隔离临时容器中完成真实 HTTP 导入验收，版本 `25.8.33.6`：v1/v2 Parquet 混合导入旧表成功，v1 JSON 成交时间和 v2 typed `trade_time_ms` 均保留，重复导出跳过，丢失本地检查点后 `FINAL` 查询仍得到正确行数。相同事件重新编码时 v2 仅减少约 0.35% 到 0.38%，因此不能把 typed 时间列描述成主要容量解决方案。生产外部 ClickHouse 仍未配置，服务器不启动常驻 ClickHouse。
