# 本地计算与服务器即时兜底

服务器仍是唯一账户/模拟账本和订单执行端。本地电脑只处理公开特征，不能接管仓位，
也没有 Binance 账户凭据。目标是可测量、可回退地分担信号计算，不承诺更低端到端延迟。

## 使用

打开 outputs/compute-assistant/AI-Trader-Compute.exe，同目录放 compute-config.json。
本机配置已经生成，包含 SSH 主机、密钥路径和独立的计算服务访问令牌；不含币安密钥。
启动按钮建立 SSH 本地端口转发；停止按钮或退出窗口后，服务器无需重新部署就继续计算。
配置包含访问令牌，不应上传 Git、分享或放在公网目录。Windows ACL 限于当前用户和 SYSTEM。

## 数据与计算

1. 服务器公开行情采集器继续重建候选盘口和生成因果特征。
2. 独立 compute-bridge 读取 Redis 公开特征，单个 WebSocket 连接一次最多 40 个输入，
   每条消息最多 512KiB，不建立无界消息积压。
3. 客户端通过受信 SSH 通道获得服务器实际部署的三份策略源码，固定文件名白名单和
   SHA256 检查，加载为独立模块。不会自动下载 GitHub 最新策略或更改线上策略网格。
4. 每条结果绑定 feature row、policy、code_id 的完整哈希，及 generation/session/batch ID。
   客户端只能返回固定策略集合的 long/short/hold 数值观察，不提供下单、清仓、杠杆权限。
5. 服务器仍检查模型状态、特征/盘口新鲜度、资金、费用、杠杆和持仓风险后模拟执行。

## 即时兜底与准入

服务器计算线程永远不等待本地回包。缺失、不匹配或超过 1500ms 的缓存返回时，
立即调用服务器原策略函数；客户端断线或桥接服务重启会使旧连接结果失效。
Redis 故障也不额外关闭服务或停止已有保护，原有行情不可用门槛继续有效。

每个新连接重新累计 RTT，至少 20 个样本、P95 <=100ms 才能成为可采用的计算来源。
本地/服务器时钟不参与跨机租约：任务往返用服务器单调时钟测量，缓存年龄由服务器
时间判断。Redis Lua 的 generation/session 围栏拒绝旧桥接进程发布，结果有限 TTL。
此处是计算结果围栏；没有两个交易节点争抢执行权，不需要迁移模拟资金或仓位。

模型验证和交易信号节奏保持原部署值。跨网往返大于策略本身计算时，计算分担可能
更慢，所以准入失败时保留服务器计算，不为“本地优先”强行制造等待。

## 发布与验证

服务器新增 compute-bridge，只绑定 127.0.0.1:18765，客户端经 SSH 转发访问；
不开放 Redis 公网端口，不向本地复制生产 env，不改变生产 API 权限。
从既有 worker 镜像精确叠加 compute 模块和 1 秒策略补丁。API 使用原已部署版本。
生产只读观察器、采集器和训练器不重建；模拟账本在更新前做 SQLite 一致性备份。

本次最终本地回归 660 项通过、4 项跳过（含 2 项独立 Redis 测试）；相关测试
73 项通过，独立 Redis/WebSocket 部署集成 18 项通过。测试包含：
输入/策略版本变化、过期回包、并发客户端拒绝、断线立即兜底、桥接代际围栏、
Redis 故障、本地策略结果与同版本服务端逐项一致。PyInstaller EXE 已实际计算公开输入，
生产 API 200、模拟 worker running/无错误，实盘执行仍关闭。

实测本地无法直连 Binance 深度流，服务器转发可用；但 EXE 测试往返 P95 约 1225ms，
因此本地未通过 100ms 准入，服务器继续自行计算。这不是毫秒级交易验收或盈利证明。
