# 可复查的策略研究与原模拟盘修复

本工具只研究历史数据，不写模型文件、不写模拟订单，不调用 AI 或交易接口。
原模拟账本、余额与历史保留。DS 关闭；模拟执行待命，严格验证未通过时禁止新仓，实盘保持关闭。

## 修复的口径

- `microstructure_plan` 供在线模拟、抽样回放、逐事件回放共同使用，包含成本、动态杠杆、保证金预算和流动性上限。
- 旧实现只有探索模式允许把 2,000 U 作为上限；严格模式要求完整预算，造成大量流动性拒单。现以独立的 `QUANT_PAPER_MARGIN_IS_CEILING=true` 明确把预算作为上限，严格模式也可按盘口缩小；验证门槛保持不变。该设置写入策略指纹，旧验证结果不能冒充新版本证据。
- 抽样回放输出拒单原因、持仓期间数据间断、实际资金与杠杆，缺少连续报价不能通过研究门槛。
- 训练用有效标签；验证成交路径用该时间窗口的全部有效报价，不能用未来标签是否有效来筛选行情。
- 反思统计从持久化完整开平仓周期重建。多个盘口成交、部分平仓只计一个最终完成的持仓，合计双边费用并计算持仓时长。
- 首次迁移移除旧成交碎片计数生成的币种冷却，但不改账本、交易记录或已启用的成本过滤，也不按历史碎片重新放大风险。
- 历史统计改成 SQLite JSON 条件聚合，避免 API 把几十万条元数据一次性加载进内存。页面读共享后台缓存，首次返回计算中，后续保留统计时间；训练仍读取新统计，不用缓存作为放行依据。
- 候选币池轮换改成 Binance 公共 WebSocket 的动态 `SUBSCRIBE/UNSUBSCRIBE`。离开候选池的币在一个完整标签/持仓观察窗口内保留盘口订阅，避免把正常换池记录成整池断线；真实连接断开仍写入 `feedStatus` 和缺口证据。
- 早先仅运行约 3 分钟的健康快照没有覆盖真实轮换，不能证明后续换池连续性。历史库的未修复缺口仍保留。

## 2026-11-11 连续报价与自动待命修复

- `execution_quotes` 单独保存有效深度报价；只在该时刻没有完整特征时写入，避免重复向量和交易规则。特征预热、OFI 预热、离池观察均不再导致退出路径消失。
- 报价没有预测向量，不进入训练标签；`entry_allowed=false` 禁止生成新信号。候选币的既有挂单可使用后续有效报价成交，离池则取消旧的待开仓信号；持仓退出不受新仓资格影响。
- 盘口实际保留期间也保留逐笔成交证据和特征观察，重入不会无谓重置连续历史；进程重启从持久化特征恢复观察尾部，但不伪造重启期间的连续行情。
- 订阅变更等待 Binance ACK，拒绝或超过 10 秒未确认会重连；30 秒没有市场消息也重连。正常退出观察写入明确的 retirement 控制记录，不冒充连接断开；模型回放必须证明币种已离池且经过完整观察期，持仓/挂单退出观察或真实缺口仍判无效。
- 逐事件验证协议升级到 v4；旧协议的通过凭据不能自动批准新版。
- 页面 `/api/quant/lab/status` 的 `opening` 区分开关、暂停、Redis、行情、特征和策略验证失败，并列出扣费测试收益。探索模型不再显示为“历史验证通过”。
- 服务器配置模拟执行开启、探索关闭、`lab_model` 严格门槛开启。只有相同模型版本与执行配置通过时间隔离的样本外及逐事件测试，才自动检查实时信号；不保证立即产生交易。DS 和实盘关闭。
- 每个拟合模型使用最多 120,000 条方向/概率缓存，跨阈值和压力回放复用推断，不复用未来行情、不改变测试选择规则。本地 2,000 条、六个阈值对比，方向逐条一致，推断计算约快 6.79 倍；这不是整个训练流程的提速承诺。

主流八币的固定 10 天诊断比较也未通过，见 `research/20261111-stable-last10d.json`（312,640 个报价、61,815 个标签）。这个已经观察过的窗口不能再称为新策略的独立留出集。失败涉及旧报价缺口、净收益为负和交易数不足，不能靠换币种解决。

v1 部署实际观察两次池轮换：4 条动态订阅确认，0 条待确认，活动盘口缺口/成交缺口/重连/错误均为 0。BTC 约 15 分钟窗口 162 个有效报价，其中 24 个为纯报价，最大间隔 10.584 秒。这只证明该短时窗口连续，不能证明策略盈利或覆盖旧数据缺口。v2 又补齐实际订阅尾部逐笔归档与推断缓存，最终部署结果单独记录。

v2 部署后也实际观察到动态订阅确认与特征重新就绪，未发现活动盘口缺口、成交缺口、重连或采集错误。BTC 500 秒诊断区间的逐事件回放有效，27,541 条事件、7,562 次重建深度更新、0 序号缺口；模型没有方向信号，0 交易。这是数据链路检查，不能宣称盈利策略通过。报告：`research/20261111-btc-event-smoke.json`。

原始诊断曾错误地把仅回放 BTC 时其他币种的全局退订控制记录也当成 BTC 失败。v3 将控制影响限定在实际观察/持仓/挂单的币种，并从候选控制历史跟踪退出观察期；单元测试继续拒绝持仓断流、真实序号缺口和过早退订。跨重启的旧诊断里真实成交缺口仍然拒绝，不用新版伪造连续性。

严格固定保证金的完整训练确实完成，但三个测试折均 0 成交，拒单多为风险/流动性不支持固定预算（400、231、207 次）。报告 `research/20261111-strict-training-report.json` 是修正 sizing 前的诊断，不是新配置结果。v4 引入独立保证金上限设置、执行计划协议 v2；下单量更小仍需满足最小数量、手续费、价差、最低杠杆及组合风险，不恢复探索模型或 AI，不降低样本外门槛。

使用原始 PONS 事件的限额成交诊断确实产生 1 个完整开平仓周期、双边手续费约 0.01035 U，扣费净收益约 -0.05107 U。回放有 1 个真实成交序号缺口，因此 `valid=false`，明确禁止晋级；它只证明模拟撮合可以成交，不证明策略有优势。诊断在临时账本执行，原模拟盘余额 979,536.7083798334 U、4,613 条历史成交和空仓均保留。报告 `research/20261111-pons-execution-diagnostic.json`。

验证：Python 测试 460 通过、2 跳过；TypeScript/Vite 构建成功。数值推断缓存和动态订阅均无 DS 调用。发布只更新量化相关容器与页面，不操作真实交易接口。

最终按盘口缩小保证金的完整训练已完成，模型 `82eac258134c61824e7ff1f3`：三个测试折分别成交 202、98、77 个周期，扣费净收益约 -100.40、-11.12、-19.25 U，均有历史持仓报价缺口，`approved=false`。完整结果 `research/20261111-bounded-margin-training-report.json`。说明固定金额造成的零成交问题已解除，但不能证明盈利优势，不能批准开仓。实际模拟盘保持严格门槛待命、原账本空仓；现有自动训练继续复查，达到同版本/同策略指纹的完整验证才允许检查新仓信号。等待本身不保证模型会通过。

用户明确要求继续到原模拟盘实际开仓。当前运行方式调整为**显式的模拟前向试验**，取代上文“严格门槛待命”的运行配置；历史失败报告与 `approved=false` 保留，不把试验许可当成样本外验证通过。

- 使用原 `quant-aggressive-paper.db`、原余额和完整历史；不新建替代账户，不手写成交。只有模型给出方向信号且实时盘口、费用、数量过滤、保证金、组合风险检查通过后，才提交虚拟 IOC 订单。
- `QUANT_PAPER_EXPLORATION_MODE=true` 仅授权未通过验证的数值模型在模拟盘前向观察；试验方向阈值最初 0.45，因信号稀少调整到配置允许下界 0.40，并在原账本记录参数变更。观望类别与已有成本检查保留，不强制产生方向。实盘与 DeepSeek 自动调用关闭，模拟 worker 内无币安账户密钥。阈值调整不构成收益改善证据。
- `paper_trial.py` 在原账本记录一次开始基线，重启不重置；状态接口从持久化订单与成交表汇总本轮真实虚拟成交，区分“提交订单”“成交开仓”“成交平仓”和逐价位成交明细。
- 页面同时显示允许执行的运行条件与独立的验证警告；原模型文件、失败证据不修改，模型版本跟随每笔订单保存。
- 修复按标记价定量后、盘口价差/滑点导致实际保证金略超上限的问题：共享撮合器对开仓累计实际名义金额设置预算，按 Decimal 向下截量，未完成部分如实过期，退出不受开仓预算限制。采样回放已经按实际成交价限制金额，逐事件回放与模拟执行现在也使用相同预算边界。执行策略指纹升级到 `shared-microstructure-v3-quote-budget`，旧验证不能冒充新配置的通过证明。
- 回归测试 465 通过、2 跳过；包含原引擎端到端虚拟开平仓、重启基线保留、买卖双向预算限制及不能接触实盘接口。TypeScript/Vite 构建通过；既有大 bundle 提醒仍存在。

允许前向试验不证明存在盈利优势。运行成交证据另存报告；本轮不会据此自动开启实盘或恢复付费 AI。

## 固定比较

三个预先定义的候选：固定 0.60 阈值的数值模型、成本过滤的动量跟随、订单流确认的短期反转。
每个候选使用相同资金和成本假设；三个扩展时间折中，训练标签结束时间必须早于训练边界。
只用验证集选择候选，测试和成本加压结果只能接受或淘汰该选择，不反过来改参数。

```powershell
$env:PYTHONPATH='service/server'
$env:OMP_NUM_THREADS='1'
$env:OPENBLAS_NUM_THREADS='1'
python -m quant.strategy_research --input research-input.jsonl.gz --policy-json policy.json --start-ms START --end-ms END --output comparison.json
```

也支持 `--database` 只读查询历史 SQLite 库；活跃 WAL 库无法在只读挂载中读取时，应使用一致事务流式导出固定窗口，在本地计算。
报告绑定输入 SHA256、代码 SHA256、时间边界和执行策略参数。小内存服务器只采集和导出，重计算移到本地。

## 验证边界

抽样比较只是研究筛选，不是完整盘口成交证明；采样间的价格路径、排队优先级、动态协方差及缺失的历史数量过滤仍需逐事件验证。
30 秒采样研究不能证明毫秒级或高频收益。合约费用沿用配置假设，不声称等同用户当前 VIP 实际费率。
没有候选通过时保持空仓，不能降低验证门槛、换数据窗口挑收益或通过增加杠杆把亏损策略包装成盈利策略。
即使抽样结果为正，报告的 `promotion_allowed` 仍是 `false`，还需未参与调参的完整逐事件验证及冻结参数的后续模拟观察。
