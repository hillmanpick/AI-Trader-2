# 可复查的策略研究与原模拟盘修复

本工具只研究历史数据，不写模型文件、不写模拟订单，不调用 AI 或交易接口。
原模拟账本、余额与历史保留。DS 和新开仓维持关闭，直到有新的有效证据。

## 修复的口径

- `microstructure_plan` 供在线模拟、抽样回放、逐事件回放共同使用，包含成本、动态杠杆、保证金预算和流动性上限。
- 探索模式下 2,000 U 是单仓保证金上限，盘口不足时缩小；严格模式仍要求支持完整预算。两者写入策略指纹，旧验证结果不能冒充新版本证据。
- 抽样回放输出拒单原因、持仓期间数据间断、实际资金与杠杆，缺少连续报价不能通过研究门槛。
- 训练用有效标签；验证成交路径用该时间窗口的全部有效报价，不能用未来标签是否有效来筛选行情。
- 反思统计从持久化完整开平仓周期重建。多个盘口成交、部分平仓只计一个最终完成的持仓，合计双边费用并计算持仓时长。
- 首次迁移移除旧成交碎片计数生成的币种冷却，但不改账本、交易记录或已启用的成本过滤，也不按历史碎片重新放大风险。
- 历史统计改成 SQLite JSON 条件聚合，避免 API 把几十万条元数据一次性加载进内存。页面读共享后台缓存，首次返回计算中，后续保留统计时间；训练仍读取新统计，不用缓存作为放行依据。

## 固定比较

三个预先定义的候选：固定 0.60 阈值的数值模型、成本过滤的动量跟随、订单流确认的短期反转。
每个候选使用相同资金和成本假设；三个扩展时间折中，训练标签结束时间必须早于训练边界。
只用验证集选择候选，测试和成本加压结果只能接受或淘汰该选择，不反过来改参数。

```powershell
$env:PYTHONPATH='service/server'
$env:OMP_NUM_THREADS='1'
$env:OPENBLAS_NUM_THREADS='1'
python -m quant.strategy_research --input research-input.jsonl.gz --policy-json policy.json --start-ms START --end-ms END --output comparison.json
```

也支持 `--database` 只读查询历史 SQLite 库；活跃 WAL 库无法在只读挂载中读取时，应使用一致事务流式导出固定窗口，在本地计算。
报告绑定输入 SHA256、代码 SHA256、时间边界和执行策略参数。小内存服务器只采集和导出，重计算移到本地。

## 验证边界

抽样比较只是研究筛选，不是完整盘口成交证明；采样间的价格路径、排队优先级、动态协方差及缺失的历史数量过滤仍需逐事件验证。
30 秒采样研究不能证明毫秒级或高频收益。合约费用沿用配置假设，不声称等同用户当前 VIP 实际费率。
没有候选通过时保持空仓，不能降低验证门槛、换数据窗口挑收益或通过增加杠杆把亏损策略包装成盈利策略。
即使抽样结果为正，报告的 `promotion_allowed` 仍是 `false`，还需未参与调参的完整逐事件验证及冻结参数的后续模拟观察。
